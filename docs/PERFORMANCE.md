# Производительность PoP - Protocol

Все замеры: Windows 10, x64, debug/release cargo-билды; клиент — Chromium-webview (показательны *относительные* цифры, абсолютные зависят от GPU).

## Сервер

### Микробенч игрового тика (release)

Матч на 10 игроков (8 человек без ввода + 2 бота-профи), `cargo test --release bench_tick`:

| Показатель | Значение | Бюджет (30 Гц) |
| --- | --- | --- |
| Средний тик | **4.8 мкс** | 33 300 мкс |
| Доля бюджета | **0.014 %** | 100 % |

Один тик — это физика 10 ракеток и мячей, сетка коллизий, события, боты, сборка снапшота с дельтой кирпичей.

### Стресс-тест: 50 комнат × 10 игроков (500 одновременных)

`tools/stress.mjs 18409 50 30` — 30 секунд, все матчи активны, боты-профи играют:

| Показатель | Debug-сборка | Release-сборка |
| --- | --- | --- |
| CPU сервера | 253 % (~2.5 ядра) | **16.7 % одного ядра** |
| RAM сервера | 28 МиБ | **20 МиБ** |
| Нисходящий трафик | 708 КиБ/с | 708 КиБ/с (~14 КиБ/с на игрока) |
| Сообщений/с | 1517 | 1517 (91 052 снапшота за 30 с) |
| Живых комнат/матчей | 50/50 | 50/50 |

Release-ускорение игрового цикла — **~15×**. При 16.7 % ядра на 500 игроков запас сервера — порядка 3000 одновременных игроков на одно ядро (линейная экстраполяция, без учёта сети и БД).

## Клиент

Оптимизация: слой кирпичей и фон-градиент/сетка вынесены в кэшируемые Graphics-слои; перерисовка только при изменении (дельта снапшота, pop-анимация, resize, появление/исчезновение босса). Динамика (мячи, ракетки, босс, частицы) рисуется каждый кадр.

Замер `ticker.update()` (рендер + частицы + FPS-монитор), матч с кирпичами, 50 прогонов:

| Показатель | До кэша | После кэша | Выигрыш |
| --- | --- | --- | --- |
| Медиана тика | 15.0 мс | **5.8 мс** | −61 % |
| Средний тик | 95.0 мс | **7.6 мс** | −92 % |
| p95 | 466.6 мс | **26.4 мс** | −94 % |

Медиана 5.8 мс укладывается в бюджет 60 FPS (16.6 мс) с запасом ~3×; авто-деградация (отключение частиц при FPS < 45) остаётся страховкой на слабых машинах.

## Выводы

1. Узкое место мультиплеера — не физика (микросекунды на тик), а сериализация/сеть: 14 КиБ/с на игрока при 30 Гц снапшотах с дельтами кирпичей.
2. Кэширование статики в PixiJS даёт больший эффект, чем микрооптимизации динамики: кирпичи рисуются в сотни раз реже, чем обновляются.
3. Release-профиль обязателен для нагрузочных тестов: разница 15× между debug и release.
