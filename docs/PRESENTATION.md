# Презентация к защите — 12 слайдов

Тема: «Многопользовательская браузерная игра реального времени на Rust» (PoP - Protocol).
Формат: 10–12 минут доклада, каждый слайд — тезис + что говорить. Скриншоты брать из docs/img.

---

### Слайд 1. Титул
PoP - Protocol — многопользовательский кооперативный арканоид на Rust.
ФИО, группа, руководитель. Фон: скриншот gameplay.png.

### Слайд 2. Задача
- До 10 игроков в одной комнате, кооперативный арканоид.
- Серверная физика (авторитарный сервер), 30 Гц тики, 60 FPS клиент.
- Боты, события, боссы, мета (XP, лидерборды).
*Говорим:* «Цель — не ремейк, а полный сетевой стек: от бинарного протокола до нагрузочных испытаний».

### Слайд 3. Почему Rust + браузер
- Rust: производительность C без UB; tokio/axum — асинхронность без ручных потоков.
- Браузер как клиент: нулевая установка, мгновенный вход по ссылке.
- WebSocket + bincode: бинарный протокол фиксированной ширины, меньше overhead в 3–5 раз против JSON.
*Скриншот:* схема архитектуры (mermaid из README).

### Слайд 4. Архитектура
- Три крейта: core (протокол+физика) / server (лобби+матч) / bot (ИИ).
- Поток: PaddleX 40 Гц → тики 30 Гц → снапшоты 30 Гц → интерполяция.
- MongoDB: игроки, токены, XP.
*Говорим:* «Единый источник истины — сервер; клиент только рисует и предсказывает свою ракетку».

### Слайд 5. Синхронизация — главная проблема
- Интерполяция Эрмита между снапшотами: C1-гладкость без изломов.
- Адаптивная задержка 50–140 мс (1.6 × измеренный интервал).
- Предсказание своей ракетки с повтором серверной логики: задержка = 0.
- Реконнект 90 с: слот держится, ракетку ведёт бот, возврат по токену.
*Скриншот:* glass-bricks.png + подпись «сервер шлёт дельты, клиент досчитывает».

### Слайд 6. Геймплей
- 15 рукотворных уровней, финальная бронированная стена.
- 9 событий (метеориты, тьма, инверсия, золото…), 3 босса с механиками щитов/стана/ярости.
- Режимы: Кооп, Босс-раш (5 боссов), Волна (процедурные ряды, детерминированный генератор).
*Скриншоты:* final-wall.png + события.

### Слайд 7. ИИ ботов
- 3 уровня: реакция 9/4/1 тик, шум прицела 90/30/4 px.
- Прогноз точки падения с отражениями от стен — боты встают в точку, а не бегут за мячом.
- Steer-отскок: профи смещает ракетку до 34 px, чтобы направить мяч в плотные кирпичи; прицельный запуск в кластер.
*Цифра:* бот-профи набрал 190 очков за 32 с (одиночный эталон 120 до улучшений).

### Слайд 8. Клиент и «джус»
- Стеклянные кирпичи с трещинами по урону, шлейфы мячей, кольца взрывов, комбо-фейерверк.
- Генеративная музыка и все звуки — чистый WebAudio-синтез, 0 аудиофайлов.
- Авто-деградация FX при FPS < 45; RU/EN; мобильная вёрстка; палитра цветов.
*Скриншот:* палитра/чат.

### Слайд 9. Тестирование
- 82 юнит-теста (физика, лобби, боты, события, боссы, режимы, хранилище).
- E2E-скрипты WebSocket: реконнект, XP-цикл.
- GitHub Actions: fmt + clippy -D warnings + тесты + Docker — зелёный на каждый push.
*Бейдж CI + скриншот терминала тестов.*

### Слайд 10. Производительность
- Тик матча на 10 игроков: **4.8 мкс** из бюджета 33 300 мкс (0.014 %).
- Стресс 50 комнат × 10 = **500 игроков**: release 16.7 % ядра, 20 МиБ RAM, 14 КиБ/с на игрока.
- Кэш статики клиента: медиана рендера 15.0 → **5.8 мс** (−61 %), p95 −94 %.
*Таблица до/после из docs/PERFORMANCE.md.*

### Слайд 11. Надёжность
- Реконнект по токену без пароля; самовосстановление сетки кирпичей (полный ресинк раз в 3 с).
- MongoDB: толерантное чтение Int32/Int64; MemoryStore для тестов.
- Docker: multi-stage, healthcheck, compose с mongo — деплой одной командой.

### Слайд 12. Итоги и перспективы
- Итог: полный сетевой стек «протокол → сервер 30 Гц → плавный клиент 60 FPS», публичный код, CI, нагрузочные цифры.
- Перспективы: WebTransport, rollback-неткод, турниры, косметика, мобильные приложения.
- Ссылка: github.com/LeviTankTV/PoPProtocol — «играть можно прямо сейчас, сервер уже запущен».
